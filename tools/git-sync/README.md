# git-sync.sh: גיבוי אוטומטי של תיקיית העבודה

פעם בבוקר ופעם בערב הסקריפט מכניס לקומיט את מה שהשתנה, מושך מהשרת ודוחף. ככה כל העבודה, כולל ההגדרות של קלוד (דרך הקישור `claude-global`, ראו `docs/harness.md`), מגובה בגיטהאב בלי לזכור לעשות את זה.

## שלוש הגנות
סודות נשארים בחוץ. קבצי `.env`, מפתחות, טוקנים ו-`bots.json` לא נכנסים לקומיט, והסקריפט גם סורק את התוכן עצמו. אם בקובץ רגיל יש משהו שנראה כמו מפתח, הוא עוצר בלי לדחוף.

עבודה לא נמחקת. הסקריפט מקמט קודם ומושך אחר כך, ואם יש התנגשות מול השרת הוא עוצר. הקומיטים המקומיים נשארים במקום.

רק `main` מסונכרן. ענף אחר שפתוח באותו רגע נשאר כמו שהוא.

כשמשהו נתקע, הוא כותב את הקובץ `GIT-SYNC-STUCK.md` בתיקיית העבודה, עם מה קרה. כל השאר נרשם ב-`.git-sync.log`.

## הגדרה
1. תיקיית העבודה צריכה להיות ריפו של git עם `origin`. מומלץ ריפו **פרטי**.
2. משתנה סביבה `CLAUDE_WORK_DIR` עם הנתיב לתיקייה. ב-Windows: `setx CLAUDE_WORK_DIR "%USERPROFILE%\claude-work"`.
3. להוסיף ל-`.gitignore` את `.git-sync-state`, `.git-sync.log` ו-`GIT-SYNC-STUCK.md`.

## הפעלה
**בתחילת כל סשן של קלוד**: הוק `SessionStart` ב-`settings.json`:
```json
{"hooks": [{"type": "command", "command": "bash \"$HOME/.claude/tools/git-sync.sh\""}]}
```
ב-Windows זה רץ דרך Git Bash, שמגיע עם Git for Windows.

**סנכרון ידני עכשיו**, גם מחוץ לשעות הבוקר והערב:
```
CLAUDE_SYNC_ANYTIME=1 bash git-sync.sh
```

## לדעת
- זה פרסום בלי שאדם קורא לפני כן. לכן הריפו צריך להיות פרטי, וה-`.gitignore` צריך להיות מוכן לפני הסנכרון הראשון (`claude-config/templates/gitignore.template`).
- נבדק על מק מול ריפו מקומי: קומיט ודחיפה, דילוג על `.env`, ועצירה על מפתח בתוך קובץ. ב-Windows לא נבדק.
