# mem.py: תחזוקה של מאגר הזיכרון

קלוד טוען את `MEMORY.md` בכל שיחה, וזיכרונות נוטים לגדול עד שהם הופכים ליומנים. הכלי הזה מחפש במאגר בלי לטעון את כולו, ומראה מה צריך תיקון.

## פקודות
```
python mem.py find <מילים> [--deep]      # אינדקס קצר של מה שמתאים: שם, סוג, תיאור
python mem.py show <שם> [<שם>...]        # הטקסט המלא, רק של מה שנבחר
python mem.py audit                      # מצב המאגר: גודל, קבצים מנופחים, שדות חסרים, קישורים שבורים
python mem.py split <שם> [--apply]       # מוציא בלוקים מתוארכים ישנים מזיכרון שהתנפח לקובץ יומן
python mem.py fix-links [--apply]        # מתקן קישורי [[ויקי]] שבורים
```
במק: `python3` במקום `python`.

`split` ו-`fix-links` רק מציגים מה הם היו עושים. הם כותבים לקבצים רק עם `--apply`.

## איפה הוא מחפש
- ברירת המחדל: תיקיית הזיכרון של הפרויקט שבו `MEMORY.md` עודכן אחרון, תחת `~/.claude/projects/`.
- אפשר לקבוע במפורש: משתנה סביבה `MEM_DIR`, או `--dir <תיקייה>`.
- יומני `split` נשמרים ב-`memory-logs/` ליד תיקיית הזיכרון, או בנתיב שב-`MEM_LOG_DIR`.

## תקרת האינדקס
קלוד טוען את 200 השורות הראשונות של `MEMORY.md`, או את 25,000 התווים הראשונים, מה שמגיע קודם. `audit` מראה כמה נשאר עד התקרה. מה שמעבר לה פשוט לא נטען.
